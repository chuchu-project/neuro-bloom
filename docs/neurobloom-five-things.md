# 这一版做了什么（5 件事，含验证方式）

给参赛文档用。每条都写清楚「改了什么 / 怎么验证的 / 还没做的是什么」，答辩被追问时可以直接指。

## 1. 加了第二条轴：专注度（β/θ）

**改了什么**
判定层原来只输出一条「放松度」（α/β）。现在同一个窗口多算一条「专注度」= β/θ 相对个人基线的位置，
两者**共用同一次频谱计算**，不多采一份数据。

- `analysis/relax_axis.py`：新增 `focus_from_bt()`，标定期的 β/θ 中位数当作这个人的基线
- 状态消息里多一个 `focus`（0~1），和 `relax` 并列
- 控制台放松卡下方多一条「专注 β/θ」进度条

**为什么不是把两个数混成一个**
放松和专注是两件事：闭眼静坐可以很放松但不专注；盯着题目算数可以很专注但一点也不放松。
混成一个数，画面就只能表达一种状态，也解释不清「为什么我放松了画面却没变」。

**怎么验证的**
合成板跑 25 个窗口，末窗 `relax=0.611 / focus=1.0`；`world_params` 四键逐位不变（老 Unity 不受影响）。

**还没做**
Unity 里专注度只接到水晶上（见第 6 条），没有单独的画面元素。

## 2. 左右半球不对称指数

**改了什么**
16 路电极按左右各 8 路切开，分别算 α 功率，输出 `lr = {li, imbalance, left, right, n_left, n_right, notable, band}`。

- 指数定义：`LI = (右 - 左) / (右 + 左)`，范围 -1~1，正值=右侧偏强
- `|LI| > 0.15` 才算「明显」，否则只说「基本对称」，避免把噪声讲成结论
- 任意一侧有效电极少于 3 路就不出结论（`ok=False`），不硬凑

**怎么验证的**
`analysis/lateralization.py` 自带自检：构造左强数据得 `LI=-0.797`、对称数据得 `0.004`、
全饱和数据正确返回不可用。实跑一架 41 帧的会话，`|LI|` 均值 0.10，报告里给出前后半段趋势。

**还没做**
没有做源定位，也不声称「哪个脑区激活」。我们只讲「同一时刻左右差多少、训练过程中怎么变」。

## 3. 五频带构成（δ θ α β γ）

**改了什么**
每个窗口输出五个频带的绝对功率与占比，控制台「看细节」里画成柱状图（按窗口内最大值归一，标出主频段）。

**怎么验证的**
同一段数据的五频带之和与总功率一致；实跑样本 α 占 64.7%（闭眼放松，符合预期）。

## 4. 训练会话报告可导出

**改了什么**
- 桥接自动把每条状态写进 `sessions/session-*.jsonl`，断开时生成 `sessions/report-*.html`
- 报告是单文件 HTML：放松度走势、左右不对称走势、频带构成、引导语列表、信号质量，带打印样式
- 控制台顶部「导出报告」→ `http://127.0.0.1:8765/report`（`?download=1` 直接下载）

**怎么验证的**
45 秒 demo 跑完自动出报告（41 帧 / 8 KB），页面无横向溢出、两张内联 SVG 各 41 个点、
最小字号 11.5px、打印预览 A4 不截断；CLI 重渲染结果一致。

**还没做**
没有历史报告列表，也没有跨次对比曲线。

## 5. 端到端延迟实测

**改了什么**
- `eeg_service` 在每条消息里打三个时间戳：窗口结束时刻、分析耗时、窗口时长
- `tools/latency_probe.py` 连上桥接，把延迟拆成「攒窗口 / 分析 / 传输」三段

**实测（本机，合成板，步长 1 秒，25 条样本）**

| 环节 | 中位 | 95 分位 | 说明 |
| --- | --- | --- | --- |
| 攒窗口 | 4000.0 ms | — | 判定要窗口填满，这一段是设计使然 |
| 分析计算 | 0.7 ms | — | 频谱 + 判定 + 打包 |
| 传输排队 | 1.6 ms | 3.0 ms | WebSocket 本机回环 |
| 端到端 | 4002.3 ms | — | 上面三段相加 |

**答辩口径**：判定每 4 秒一次，数据凑齐到画面响应是 2~3 毫秒，瓶颈不在软件；
从「此刻的脑电」到「画面反映」最坏是 4 秒窗口 + 2 秒步长 = 6 秒。
**不要说「延迟低于 100ms」**，那是把攒窗口的时间藏起来了。

**还没做**
Unity 出图到眼镜显示这一段没测（需要头显在位），只测到桥接发消息为止。

## 6. 专注度接到水晶（Unity 侧）

**改了什么**
`NeuroWorldController` 里水晶原来只由 `crystal`（放松度派生）控制体积。现在：
放松度决定**长多大**，专注度决定**棱面清不清**（辉光强度最多 +90%、光色向冷白收敛、
体积再 +12%）。专注度缺失时按 0 处理，画面回到原样。

**怎么验证的**
编译通过、连续两次自动渲染逐像素差 0（渲染管线稳定）。**运行时效果还没人眼确认**，
需要打开 Unity 按 Play 看一眼。

**还没做**
没有为专注度做独立的画面元素（例如水面纹路、星轨）。现阶段它是「同一颗水晶的清晰度」，不是一个新物件。

## 7. 成品化：不再需要手动开 Unity

**改了什么**
新增 `Assets/Editor/NeuroBloomBuild.cs`（带 `-nbBuild` 才执行），一条命令构建出
`UnityVR/Build/NeuroBloom.app`。桥接的「开始演示」改成优先启动这个成品：全屏、自动连
`ws://127.0.0.1:8765/ws/world`，停止时让它退出。用户视角只有一个控制台网页。

**怎么验证的**
`/control/start` 返回 `{"unity":"launched"}`，1 秒内 `world` 通道出现 `role: unity`，
视频推流 1 路、单帧约 130–200 KB；`/control/stop` 返回 `{"unity":"quit"}`，进程退出。

**还没做**
Quest 一体机版本还没打（需要 Android 构建模块 + 头显），PC 版已可用。

## 一句话总结

原来只有一个数（放松度）在推画面，现在是「放松 + 专注」两条轴，配上左右半球和五频带
两个可解释的读数；训练结束自动留一份可打印的报告；延迟拆开量过，能说清每个毫秒花在哪。
