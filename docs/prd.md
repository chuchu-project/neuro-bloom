# 需求文档（MVP PRD）

> 脑境 NeuroBloom · 功能范围、验收标准与排除项

> 版本 v1.0 · 2026-11-12
> 上游：[Project Proposal](proposal.md) · 下游：[技术设计](tech-design.md) · [验证结果](verification.md)

## 1. 概述与用户

卒中后居家康复期的患者，情绪与注意力缺少可日常观察的指标；治疗师无法上门，只能等复诊。NeuroBloom 把 16 通道脑电换算成一个**相对本人基线**的指数，驱动一座三维花园实时变化，并把每次训练与随访记录留给治疗师。

目标用户与痛点见 [Proposal §2–3](proposal.md)。本 PRD 只定义 MVP：让一名患者能在无人指导下完成一次训练，让一名治疗师能看懂这次训练。

## 2. MVP 范围

五个核心功能。每一个都是主任务链条上不可省的一环——去掉任何一个，患者或治疗师就有一段流程走不通。

| # | 功能 | 为什么必须 |
| --- | --- | --- |
| 1 | 设备连接与信号质量（FR-01） | 没有可信信号，后面全部无效；坏道必须先看见 |
| 2 | 一人一基线标定（FR-02） | 绝对值不可比，没有基线就没有判定 |
| 3 | 实时判定 α/β、β/θ（FR-03） | 系统的核心换算，唯一的判定来源 |
| 4 | 三维花园实时反馈（FR-04） | 患者能感知的唯一输出，替代数字 |
| 5 | 训练会话、报告与随访（FR-05/06） | 治疗师端的价值落点，否则只是玩具 |

支撑功能：

| # | 功能 | 说明 |
| --- | --- | --- |
| 6 | 演示模式与数据水印（FR-07） | 无设备时也能评审，但必须不可混淆 |

## 3. 不在范围内（Out of Scope）

| 排除项 | 原因 |
| --- | --- |
| 疾病诊断、疗效评估、治疗处方 | 无伦理批件、无临床数据；越界会直接损害可信度 |
| 真实患者数据接入 | 本阶段未入组，仅有健康成人自测与合成信号 |
| 多用户账号、权限、云同步 | 单机单治疗师场景已覆盖 MVP；引入账号体系会带来合规负担 |
| 移动端 App | 浏览器控制台 + VR 端已覆盖当前使用场景 |
| 医疗设备注册、量产设计 | 超出本阶段范围，属于后续里程碑 M6 |
| 自动推荐训练强度 | 缺少剂量-反应证据，规则一旦写死就是伪科学 |

## 4. 用户旅程（端到端）

```
治疗师：打开控制台 → 设备页填 IP/端口 → 检测 → 连接 → 看到 16 路波形与坏道
        → 让患者坐好 → 点「开始训练」
患者：  静坐 60 秒（系统标定基线，此期间不出分、不驱动画面）
        → 画面开始响应：花开、天亮、雾散
        → 跟着呼吸条练（吸 4 秒 / 呼 6 秒）
治疗师：训练页看实时指数与画面 → 到时间点「停止」
系统：  自动收尾 → 生成 HTML 报告 → 写入会话记录
治疗师：报告页看走势、通道质量、左右不对称 → 随访页填量表 → 看趋势与风险分层
```

关键决策点：

1. **合格通道 < 8**：不下结论，界面明确提示，不拿坏数据出分。
2. **无采集板**：后端直接拒绝启动（`blocked: no-board`），界面保持空态，不补假数据。
3. **标定未完成**：不驱动画面，避免"一上来就乱跳"。

## 5. 功能需求与验收标准

### FR-01 设备连接与信号质量

连接 OpenBCI Cyton(+Daisy)，显示 16 路波形、每路 `Railed%`（贴顶比例）与 `µVrms`。

- **AC-01.1** Given 未连接任何板卡，when 打开控制台，then 波形区不绘制任何曲线，所有指标显示「—」，后端 `/control/start` 返回 `blocked: no-board`。
- **AC-01.2** Given 已连接 16 通道，when 训练进行中，then 16 路波形以 25 Hz 刷新，共用自动量程，每路显示当前 `Railed%` 与 `µVrms`。
- **AC-01.3** Given 某通道持续贴顶，when 合格通道数降到 8 以下，then 判定返回"不下结论"，界面给出明确提示而不是输出一个指数。

### FR-02 一人一基线标定

训练开始后 60 秒为标定期，取该段所有 4 秒窗的中位数作为个人基线。

- **AC-02.1** Given 开始训练，when 处于前 60 秒，then 不输出指数、不驱动画面，界面显示标定进度。
- **AC-02.2** Given 标定完成，when 后续窗口到达，then 判定使用该次会话基线，不读取任何人群常模。
- **AC-02.3** Given 重新开始一次训练，when 新会话启动，then 重新标定，不复用上一次基线。

### FR-03 实时判定 α/β 与 β/θ

4 秒窗、2 秒步进；α(8–13 Hz)/β(13–30 Hz) 得放松轴，β/θ(4–8 Hz) 得专注轴，均为相对基线的 log₂ 比值。

- **AC-03.1** Given 基线 α/β = X，when 当前窗 α/β = 2X，then 指数 = 1.0；当为 0.5X，then 指数 = 0.0；当为 X，then 指数 = 0.5。
- **AC-03.2** Given 指数序列，when 输出到界面，then 使用最近 5 个窗（约 10 秒）的因果平滑值。
- **AC-03.3** Given 指数 ≥ 0.65，then 状态标为「放松」；≤ 0.35，then「紧张」；之间为「中间」。
- **AC-03.4** Given 同一段录制的 BDF 重复回放两次，then 两次输出的指数序列逐点一致（判定是确定性的，无随机项）。

### FR-04 三维花园实时反馈

四个画面参数由指数按固定公式映射，经 WebSocket 推给 Unity。

- **AC-04.1** Given 指数 r，then `bloom=r`、`sunlight=0.25+0.75r`、`fog=1−r`、`crystal=clamp((r−0.4)/0.4, 0, 1)`，四键名称固定，Unity 逐键读取。
- **AC-04.2** Given 指数从 0.3 升到 0.9，when 画面更新，then 花朵增多、亮度上升、雾变淡、水晶由暗转亮，变化连续无跳变。
- **AC-04.3** Given 指数 < 0.34，then 场景进入夜间；0.34–0.66 为阴天；≥ 0.66 为晴天；切换带 ±0.04 滞后，避免边界抖动。
- **AC-04.4** Given 断线或消息缺键，then Unity 退回默认值，不崩溃、不锁死。

### FR-05 训练会话与报告

每次训练写入 `sessions/session-*.jsonl`，断开或停止时自动生成单文件 HTML 报告。

- **AC-05.1** Given 一次完整训练，when 点击「停止」，then 自动生成报告，控制台「导出报告」可直接打开。
- **AC-05.2** Given 报告已生成，when 打开，then 含走势、通道质量、频带构成、左右不对称、引导语记录。
- **AC-05.3** Given 报告页，when 请求 `?download=1`，then 以附件形式下载。
- **AC-05.4** Given 会话文件，then 不进仓库（`.gitignore` 排除），仅本机留存。

### FR-06 随访量表与趋势

PHQ-2 / PHQ-9 / GAD-7 录入、计分、分层；跨会话趋势与四级风险。

- **AC-06.1** Given 录入 PHQ-9，when 第 9 题（自伤念头）非零，then 直接给出红线提示，不因总分低而降级。
- **AC-06.2** Given 多次会话与量表记录，when 打开随访页，then 显示趋势与风险分层，并注明"参考，不构成诊断"。
- **AC-06.3** Given 量表历史，when 导出，then 生成 CSV。

### FR-07 演示模式与水印

- **AC-07.1** Given 无采集板，when 开启演示，then 全程显示 `SIMULATED` 水印与橙色横幅。
- **AC-07.2** Given 演示进行中，when 关闭演示，then 立刻回到空态，不残留任何演示数字。

## 6. 业务规则（Rules）

| 规则 | 值 | 依据 |
| --- | --- | --- |
| 分析窗 / 步进 | 4 s / 2 s | 4 秒窗是频率分辨率与响应速度的折中 |
| 基线段 | 60 s，取中位数 | 中位数抗瞬态伪迹 |
| 平滑 | 最近 5 窗因果平滑（≈10 s） | 避免画面抖动，且不使用未来数据 |
| 合格通道门槛 | ≥ 8 | 少于 8 路无法支撑频带估计 |
| 放松/紧张阈值 | 0.65 / 0.35 | 留出中间带，减少二元跳变 |
| 水晶起亮点 | 0.4 起，0.8 全亮 | 让"明显好转"才有可见奖励 |
| 天气阈值 | 0.66 / 0.34，±0.04 滞后 | 防边界闪烁 |
| 呼吸节律 | 吸 4 s / 呼 6 s，6 次/分 | 约 0.1 Hz 慢呼吸，常规放松引导节奏 |
| 左右不对称 | `(R−L)/(R+L)`，仅参考 | 帽子无 F3/F4，不套用 FAA 命名 |

## 7. 验收标准与成功指标

两者不能混为一谈：

- **验收标准（AC）**：系统是否按规格运行。由开发自测与回归脚本判定。
- **成功指标**：是否真的对用户有用。需在目标用户身上测，本阶段**尚未取得**。

| 成功指标 | 目标 | 现状 |
| --- | --- | --- |
| 患者无需指导完成一次训练 | ≥ 4/5 人独立完成 | 未测（计划 L3） |
| 治疗师能在 30 秒内看懂一次训练 | ≥ 4/5 人 | 未测 |
| 同一人跨天指数重复性 | ICC(2,1) ≥ 0.6 | 未测（计划 L1） |
| 闭眼/睁眼区分度 | AUC ≥ 0.7 | 未测（计划 L2） |

## 8. 开放问题

1. **A1**：居家患者能否坚持每天 15 分钟？——需 5 天连续完成率 + 治疗师访谈。
2. **A2**：治疗师是否接受趋势图替代部分电话随访？——需任务走查。
3. 8 通道轻量设备下，合格通道门槛 8 是否过于严格？（当前会频繁"不下结论"）
4. 左右半球分组依赖接线顺序（前 8 路=左、后 8 路=右）；换设备或改接线后需重新确认映射。
